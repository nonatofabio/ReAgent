# ReAgent Codebase Review & Simplification Analysis

## Objective

Perform a comprehensive code review of the ReAgent repository to identify inconsistencies, redundancies, and simplification opportunities. The goal is to make the package simpler for both humans and AI agents to understand and interact with.

## Context

ReAgent is a reactive multi-agent orchestration framework built on AWS Strands Agents SDK. Two companion documents exist in this repository:
- `INTEGRATION_PLAN.md` - Plan to integrate semantic shared memory via local_faiss_mcp
- `EDD_TEST_PLAN.md` - Evaluation Driven Development test plan

Before implementing the memory integration, we need to understand the current codebase quality and identify technical debt that should be addressed.

---

## CRITICAL: Mandatory Subagent Usage

**YOU MUST USE SUBAGENTS (Task tool) FOR ALL ANALYSIS WORK.**

Reading files, searching code, and analyzing patterns directly in your main context will consume tokens rapidly and cause context overflow. Instead, delegate ALL investigative work to subagents.

### Subagent Strategy

```
Main Agent (You)
├── Coordinates work
├── Receives summaries from subagents
├── Synthesizes findings into CODEBASE_REVIEW.md
└── NEVER reads files directly (except to write output)

Subagents (Task tool)
├── Perform all code_cerebro operations
├── Read and analyze files
├── Search for patterns
└── Return concise summaries with file:line references
```

### Required Subagent Delegation Pattern

For EVERY analysis task, use this pattern:

```python
# WRONG - Do not do this
Read(file_path="/Users/fnp/tmp/ReAgent/reagent/core/memory.py")  # Consumes YOUR tokens

# CORRECT - Always delegate
Task(
    subagent_type="Explore",

    prompt="Analyze /Users/fnp/tmp/ReAgent/reagent/core/memory.py.

            2) Any code smells or inconsistencies with file:line references,
            3) Public API surface. Be concise."

```

### Parallel Subagent Execution

Launch multiple subagents in parallel when tasks are independent:

```python

Task(subagent_type="Explore", description="Analyze adaptation.py", prompt="...")
Task(subagent_type="Explore", description="Analyze mcp.py", prompt="...")
```

### Subagent Prompts Must Request

Every subagent prompt MUST ask for:
1. **Concise summary** (not full file contents)
2. **Specific file:line references** for findings
3. **Categorized issues** (Critical/Major/Minor)
4. **Actionable recommendations**

### Phase 4: Inconsistency Detection (Via Subagent)

**Delegate pattern searching to subagent:**
```python
Task(
    subagent_type="Explore",
    description="Find codebase inconsistencies",
    prompt="""Search ReAgent codebase (/Users/fnp/tmp/ReAgent/reagent/) for inconsistencies:

    1. NAMING: Mixed camelCase/snake_case, inconsistent terminology (task vs job vs execution)
    2. PATTERNS: Different approaches to similar problems, mixed async/await usage
    3. API: Functions with similar purposes but different signatures
    4. CONFIG: Hardcoded values, scattered configuration

    Use code_cerebro_pattern_search and Grep to find patterns.
    Return: categorized list of inconsistencies with file:line references.
    MAX 600 words."""
)
```

Search for specific inconsistencies:

1. **Naming Inconsistencies**
   - Mixed naming conventions (camelCase vs snake_case)
   - Inconsistent terminology (e.g., "task" vs "job" vs "execution")
   - Abbreviated vs full names

2. **Pattern Inconsistencies**
   - Different approaches to similar problems
   - Inconsistent use of async/await
   - Mixed error handling patterns (exceptions vs return codes)

3. **API Inconsistencies**
   - Functions with similar purposes but different signatures
   - Inconsistent parameter ordering
   - Mixed return types for similar operations

4. **Configuration Inconsistencies**
   - Hardcoded values that should be configurable
   - Configuration scattered across files
   - Inconsistent defaults
